# RBAC Implementation Report

## 1. Executive Summary

**Status:** Core RBAC is implemented and functional. **Not production-ready** — seed data is missing, error handling is inconsistent, and no deployment infrastructure exists.

**Major Achievements:**
- Complete Role-Permission data model with `django-simple-history` audit trail
- JWT auth with 1h access / 30d refresh token rotation
- Three permission classes (`HasPermission`, `HasRoleLevel`, `IsSuperAdmin`) with caching and automatic invalidation
- 28 permission codes across 8 domains, enforced across all 4 ViewSets at the action level
- 91 tests passing across 10 files

**Remaining Work:** Seed data, RoleService tests, error type unification, database indexes, code cleanup.

## 2. Current Architecture Status

### Authentication
- Email-based User model with JWT via `rest_framework_simplejwt`
- Permission cache warmed on login; all endpoints authenticated by default
- **No rate limiting, account lockout, or password expiry**

### Authorization
- `HasPermission(code)` — checks cached permission codes
- `HasRoleLevel(min_level)` — compares role level against threshold
- `IsSuperAdmin` — checks `user.is_superuser` (not role name, resilient to renames)
- RolePermission endpoints restricted to superusers only

### Testing
- 91 tests: services (29), auth/JWT (18), enforcement (14), integration (6), model/serializer views (24)
- Factory Boy factories, isolated test settings (in-memory SQLite, DummyCache, fast hasher)

### Security
- Global `IsAuthenticated` default; `PermissionCode` enum prevents stringly-typed codes
- `User.role` FK uses `on_delete=PROTECT`; full audit history on all RBAC models
- **CORS hardcoded to localhost; no HTTPS in dev; `.env` contains hardcoded DB password**

### Infrastructure
- Nginx directory exists but is empty; frontend directory is empty
- No deployment documentation; ERD in `docs/` is outdated

## 3. Outstanding Issues

### High Priority
- **No seed data:** No management command, migration, or fixture to create default roles. Fresh database returns 403 on every protected endpoint.
- **RoleService untested:** 6 methods (create, update, delete, assign, get, list) have zero test coverage.
- **Inconsistent error types:** `PermissionService` raises `Http404`, `RolePermissionService` raises `ValidationError`, `RoleService` lets `DoesNotExist` bubble into a 500.
- **6 missing `db_index`:** `Role.level`, `Role.is_active`, `Permission.is_active`, `User.role`, `User.is_active`, `User.is_deleted`.
- **`AUTH_USER_MODEL` duplicated** in both `base.py` and `security.py`.

### Medium Priority
- **`setattr` without field whitelist** in `update_permission` and `update_role` allows setting arbitrary fields
- **Redundant `full_clean`** called in both service and model `save()`
- **`LocMemCache` not overridden in `prod.py`** — no shared cache between workers
- **Fragile test detection** in `dev.py`: `"test" in sys.argv` matches any argument containing "test"
- **Unused `PermissionService` instance** in `PermissionViewSet` (all methods are `@staticmethod`)
- **Cache invalidation signal untested** — no test for `RolePermission` `post_save`/`post_delete`
- **Django built-in `auth_group`/`auth_permission` tables still active**, potentially confusing operators

### Low Priority
- Missing type hints on permission and auth classes
- Missing `MinLengthValidator` on `Role.name`, `Permission.name`, `Permission.code`
- `__all__` exports in init files contain class objects instead of strings
- No `@transaction.atomic` on `delete_role` or `delete_permission`
- Outdated ERD documentation

## 4. Test Coverage

91 tests across 10 files. **Key gaps:** RoleService methods, cache invalidation signals, and UserViewSet permission enforcement are untested. Some tests bypass service validation by using the ORM directly.
