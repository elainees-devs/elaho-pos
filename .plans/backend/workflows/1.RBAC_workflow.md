## Architecture Overview

The RBAC system follows a layered architecture with strict separation of concerns:

```
HTTP Request
    │
    ▼
┌──────────────┐
│   URL Router  │  config/urls.py -> apps/roles/urls.py
│              │  Routes to the correct ViewSet
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  Middleware   │  shared/middleware.py
│              │  Stores request in context variable
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  Permission  │  shared/permission.py
│  Check       │  Global IsAuthenticated + action-level HasPermission
└──────┬───────┘
       │
       ▼
┌──────────────┐
│   ViewSet    │  apps/roles/views/*.py, apps/users/views.py
│              │  Handles HTTP, delegates to service layer
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  Serializer  │  apps/roles/serializers/*.py
│              │  Validation, delegates create/update to service
└──────┬───────┘
       │
       ▼
┌──────────────┐
│   Service    │  apps/roles/services/*.py
│              │  Business logic, validation, DB queries
└──────┬───────┘
       │
       ▼
┌──────────────┐
│    Model     │  apps/roles/models/*.py
│              │  Data + normalization + history tracking
└──────────────┘
```

**Key design principles:**
- Views handle HTTP only -- no business logic
- Serializers handle validation only -- delegate persistence to services
- Services encapsulate all business rules
- Models store data + lifecycle hooks (normalization, history)
- Permission enforcement is at the view layer (gate before execution)

### Role (`apps/roles/models/role.py`)

Stores role definitions. A role groups users under a common category.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `name` | CharField(50) | unique, required | Unique role name (e.g. SuperAdmin, Manager, Staff) |
| `description` | TextField | blank=True | Optional role description |
| `level` | PositiveSmallIntegerField | default=1 | Hierarchy level (higher = more senior) |
| `is_active` | BooleanField | default=True | Whether the role is active |
| `created_at` | DateTimeField | auto_now_add | Creation timestamp |
| `updated_at` | DateTimeField | auto_now | Last modification timestamp |

**Lifecycle:**
- `clean()` -- normalizes `name` to title case, strips whitespace
- `save()` -- calls `full_clean()` before persisting
- `history` -- `HistoricalRecords()` tracks all changes

**Relations:**
- `role.permissions` -- reverse FK from `RolePermission` (permissions assigned to role)
- `role.users` -- reverse FK from `User` (users with this role)

### Permission (`apps/roles/models/permission.py`)

Stores individual system permissions that can be assigned to roles.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `name` | CharField(100) | required | Display name (e.g. "Create User") |
| `code` | CharField(100) | unique, required | Canonical code (e.g. "user.create") |
| `description` | TextField | blank=True | Optional description |
| `is_active` | BooleanField | default=True | Whether the permission is active |
| `created_at` | DateTimeField | auto_now_add | Creation timestamp |
| `updated_at` | DateTimeField | auto_now | Last modification timestamp |

**Lifecycle:**
- `clean()` -- normalizes `name` to title case, `code` to lowercase
- `save()` -- calls `full_clean()` before persisting
- `history` -- `HistoricalRecords()` tracks all changes

**Relations:**
- `permission.roles` -- reverse FK from `RolePermission` (roles that have this permission)

### RolePermission (`apps/roles/models/role_permission.py`)

Many-to-many link table between Role and Permission.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `role` | FK(Role) | CASCADE, required | Role receiving the permission |
| `permission` | FK(Permission) | CASCADE, required | Permission granted to the role |
| `created_at` | DateTimeField | auto_now_add | Assignment creation timestamp |
| `updated_at` | DateTimeField | auto_now | Last modification timestamp |

**Constraints:**
- `UniqueConstraint(fields=["role", "permission"])` -- prevents duplicate assignments

### User (`apps/users/models.py`)

Custom user model extending `AbstractUser`.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `email` | EmailField | unique, required, db_index | Login identifier |
| `first_name` | CharField(50) | MinLengthValidator(2) | User's first name |
| `last_name` | CharField(50) | MinLengthValidator(2) | User's last name |
| `phone` | CharField(20) | blank=True | Optional phone number |
| `role` | FK(Role) | PROTECT, null/blank | Assigned role |
| `is_active` | BooleanField | default=True | Account active |
| `is_deleted` | BooleanField | default=False | Soft-delete flag |
| `updated_at` | DateTimeField | auto_now | Last modification |

**Authentication:**
- `username = None` -- email-based auth
- `USERNAME_FIELD = "email"`
- Custom `UserManager` with `create_user()` and `create_superuser()`

## Authentication Flow

### JWT Token Acquisition

```
Client                          Server
  │                                │
  │  POST /api/v1/auth/login/      │
  │  { "email": "...",             │
  │    "password": "..." }         │
  │ ─────────────────────────────► │
  │                                │  Validate credentials
  │                                │  via Django auth backend
  │                                │
  │  200 {                        │
  │    "access": "<JWT>",         │
  │    "refresh": "<token>"       │
  │  }                            │
  │ ◄───────────────────────────── │
  │                                │
  │  POST /api/v1/auth/refresh/    │
  │  { "refresh": "<token>" }      │
  │ ─────────────────────────────► │
  │                                │  Validate refresh token
  │  200 {                        │
  │    "access": "<new JWT>"      │
  │  }                            │
  │ ◄───────────────────────────── │
```

### Token Configuration

| Setting | Value | Source |
|---------|-------|--------|
| Access token lifetime | 1 hour | `SIMPLE_JWT.ACCESS_TOKEN_LIFETIME` |
| Refresh token lifetime | 30 days | `SIMPLE_JWT.REFRESH_TOKEN_LIFETIME` |
| Rotate refresh tokens | Yes | `SIMPLE_JWT.ROTATE_REFRESH_TOKENS = True` |
| Auth header type | Bearer | `SIMPLE_JWT.AUTH_HEADER_TYPES = ("Bearer",)` |
| Header format | `Authorization: Bearer <token>` | standard |

### Authentication Classes (order matters)

1. `SessionAuthentication` -- for Django admin and browsable API
2. `JWTAuthentication` -- for API clients (mobile, web frontend)

Global default permission: `IsAuthenticated` -- all endpoints require authentication.

## Permission Enforcement

Three permission classes are defined in `shared/permission.py`:

### 1. `HasPermission(code)` -- Factory

Creates a DRF permission class checking for a specific permission code.

**Decision flow:**

```
has_permission(request, view)
  │
  ├── user exists and is authenticated?
  │     No ──► return False
  │
  ├── user has a role (user.role is not None)?
  │     No ──► return False
  │
  ├── permission_code in _resolve_perm_codes(user)?
  │     No ──► return False
  │
  └── return True
```

**Permission code resolution (`_resolve_perm_codes`):**

Caches permission codes per-role with a 300-second TTL in Django's `LocMemCache`:

```
_resolve_perm_codes(user)
  │
  ├── user.role exists?  No ──► return frozenset()
  │
  ├── cache.get("perm_codes_{role.pk}") hit?
  │     Yes ──► return cached frozenset
  │
  ├── Query: role.permissions.values_list("permission__code", flat=True)
  │     ──► frozenset of canonical codes
  │
  ├── cache.set("perm_codes_{role.pk}", codes, timeout=300)
  │
  └── return codes
```

Cache invalidated automatically via signal (`apps/roles/signals.py`) on every `RolePermission` post_save / post_delete:

```
RolePermission saved/deleted
  │
  └── cache.delete("perm_codes_{instance.role_id}")
```

**Auth-layer prefetch (`shared/auth.py`):**

Custom `JWTAuthentication` and `SessionAuthentication` subclasses call `_prefetch_user_permissions(user)` on successful authentication, warming the cache before the first permission check.

**Usage in ViewSets:**

```python
def get_permissions(self):
    permissions = super().get_permissions()
    if self.action in ("list", "retrieve"):
        permissions.append(HasPermission(PermissionCode.ROLE_VIEW)())
    elif self.action == "create":
        permissions.append(HasPermission(PermissionCode.ROLE_CREATE)())
    elif self.action in ("update", "partial_update"):
        permissions.append(HasPermission(PermissionCode.ROLE_UPDATE)())
    elif self.action == "destroy":
        permissions.append(HasPermission(PermissionCode.ROLE_DELETE)())
    return permissions
```

### 2. `HasRoleLevel(min_level)` -- Factory

Checks if the user's role level meets or exceeds a minimum threshold.

**Decision flow:**

```
has_permission(request, view)
  │
  ├── user exists and is authenticated?  No ──► False
  ├── user has a role?                   No ──► False
  ├── role.level >= min_level?           No ──► False
  └── True
```

### 3. `IsSuperAdmin` -- Class

Hard-coded check that the user's role name is "SuperAdmin" (case-insensitive).

```python
return role.name.lower() == "superadmin"
```

### Context Variable Middleware

`CurrentRequestMiddleware` (`shared/middleware.py`) stores the current request in a `contextvars.ContextVar`, making `get_current_user()` available application-wide via `shared/thread_local.py`. Unlike `threading.local`, `ContextVar` is natively safe for both synchronous threads and asynchronous task contexts.

```
Request arrives ──► middleware.__call__()
                       │
                       ├── set_current_request(request)
                       ├── response = get_response(request)
                       └── set_current_request(None)
```

## Request Lifecycle

Complete trace of an authenticated API request through the system.

### Example: Create a Role

```
1. HTTP Request
   POST /api/v1/roles/roles/
   Authorization: Bearer <JWT>
   Body: {"name": "Manager", "level": 50}

2. URL Routing (config/urls.py)
   Matches "api/v1/roles/" -> apps/roles/urls.py
   Matches "roles/" -> RoleViewSet.create()

3. Middleware (shared/middleware.py)
   CurrentRequestMiddleware.__call__()
     -> set_current_request(request)

4. Authentication (config/settings/security.py)
   JWTAuthentication.authenticate() (shared/auth.py)
     -> Decodes JWT, finds User by email
     -> Sets request.user
     -> _prefetch_user_permissions(user): warms perm cache

5. Permission Check (shared/permission.py)
   Global: IsAuthenticated -> True (user exists)
   Action-specific: HasPermission(PermissionCode.ROLE_CREATE)()
     -> _resolve_perm_codes(user)
     -> cache check OR DB query -> frozenset of codes
     -> permission_code in frozenset -> True/False

6. ViewSet (apps/roles/views/role.py)
   RoleViewSet.create()
     -> Gets serializer with request data
     -> serializer.is_valid(raise_exception=True)

7. Serializer (apps/roles/serializers/role.py)
   RoleSerializer.create(validated_data)
     -> Delegates to RoleService.create_role()

8. Service (apps/roles/services/role_service.py)
   RoleService.create_role(**data)
     -> Validates name uniqueness
     -> Role.objects.create(**data)
     -> Returns Role instance

9. Model (apps/roles/models/role.py)
   Role.save()
     -> role.full_clean() (calls clean() + field validation)
     -> clean(): normalizes name to title case
     -> super().save()
     -> HistoricalRecords records the change

10. Response
    HTTP 201 Created
    Body: {"id": 1, "name": "Manager", "level": 50, ...}

11. Cleanup
    Middleware: set_current_request(None)
```

### Permission Check Detail (HasPermission)

```python
# shared/permission.py
def HasPermission(permission_code):
    class _HasPermission(BasePermission):
        def has_permission(self, request, view):
            user = request.user
            if not user or not user.is_authenticated:
                return False
            role = getattr(user, "role", None)
            if role is None:
                return False
            # SQL: SELECT EXISTS(
            #   SELECT 1 FROM role_permissions rp
            #   JOIN permissions p ON p.id = rp.permission_id
            #   WHERE rp.role_id = <role.id>
            #   AND p.code = <permission_code>
            # )
            return role.permissions.filter(
                permission__code=permission_code
            ).exists()
    return _HasPermission
```

## Audit History

`django-simple-history` is configured on three models, automatically tracking all CRUD changes.

### Tracked Models

| Model | History Table | Tracks |
|-------|--------------|--------|
| `Role` | `roles_historicalrole` | Who changed what on Role records |
| `Permission` | `roles_historicalpermission` | Who changed what on Permission records |
| `RolePermission` | `roles_historicalrolepermission` | Who changed what on assignments |

### What Each History Record Captures

- All model field values at the time of change (snapshot)
- The user who made the change (via context variable middleware)
- The timestamp of the change
- The history type (`+` = created, `~` = updated, `-` = deleted)
- The history change reason (if provided)

### Accessing History

```python
role = Role.objects.get(pk=1)
role.history.all()           # All historical versions
role.history.latest()        # Most recent change
role.history.first()         # Original creation record

# Query by history type
role.history.filter(history_type="+")   # Creation records
role.history.filter(history_type="~")   # Update records
role.history.filter(history_type="-")   # Deletion records
```

### Middleware Integration

`CurrentRequestMiddleware` stores the current request in a `contextvars.ContextVar`, which `django-simple-history` uses to automatically record `history_user` on each change -- no manual wiring needed.

### `config/settings/base.py` -- Cache

```python
CACHES = {
    "default": {
        "BACKEND": "django.core.cache.backends.locmem.LocMemCache",
    }
}
```

Permission codes cached per-role (key: `perm_codes_{role.pk}`) with 300-second TTL. In tests, `dev.py` detects `"test" in sys.argv` and switches to `DummyCache` to prevent stale cache collisions between test cases.
